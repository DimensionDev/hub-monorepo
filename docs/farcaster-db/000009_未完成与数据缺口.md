### 公开节点可查到注册基线

公开兼容服务Hypersnap（https://haatz.quilibrium.com）已实测无需API Key可读/v1/info与/v1/onChainEventsByFid。用event_type=EVENT_TYPE_ID_REGISTER查询897299、1069937、3346614、3351620、1607387，五个均返回Register，包含原始注册区块、时间、交易哈希、注册时托管地址与恢复地址。完整响应保存于项目reports/public-hub-fid-registrations.json。

这说明当前source缺注册，不代表外部节点没有相应数据。该服务是兼容实现，响应的注册事件类型是Register；不能仅使用官方示例的ID_REGISTER_EVENT_TYPE_REGISTER字符串过滤。它这次没有返回source已知的后续转移/恢复地址变更，因此只能作为待核验的注册基线来源，不能当作完整历史覆盖source已有事件。注册时地址也不能直接当作当前地址。后续应核对链上交易，并在采集侧合并完整历史。此次没有写入source/target，没有修改REGISTER规则。

## 记录规则

每项记录说明业务表、字段或整条记录、受影响主键、原因、当前处理方式和恢复方法。区分：缺少来源、历史覆盖不足、规则尚未确认、代码尚未实现。不能把“还没写代码”写成“源数据无法提供”。

必填字段缺失时，不猜固定值，不把 reference 业务记录复制过来补齐；将受影响记录保留为待补全。可空字段如果暂时留空，必须说明是缺数据还是确实没有值。由程序生成的 UUID、created_at、updated_at 与 reference 不同，是目标记录的管理字段，不是源数据缺失。
