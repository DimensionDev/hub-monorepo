# Shuttle on this VM

Generated by Terragrunt/OpenTofu. PostgreSQL and Redis are managed TencentDB
instances on the private network; this VM only runs the shuttle containers.

The Snapchain node serves **shard_index 1 and 2**, and shuttle subscribes to one
shard per process, so compose runs `shuttle-1` and `shuttle-2`.

## Files

| Path | Purpose |
| --- | --- |
| `/opt/shuttle/.env` | connection strings + secrets (0600, generated) |
| `/opt/shuttle/docker-compose.yml` | one subscriber per shard + optional worker |
| `/opt/shuttle/Dockerfile` | builds the pinned `@farcaster/shuttle` release (Node 24) |
| `/opt/shuttle/shuttle.service` | systemd unit (not enabled by default) |
| `/opt/shuttle/scripts/seed-last-event.sh` | seed the per-shard "start from now" cursors |
| `/opt/shuttle/scripts/redis-cli.sh` | redis-cli wrapper that handles TencentDB auth |

## First run

```bash
cd /opt/shuttle

# 1. Only if you want "new events from now" instead of the retained history:
#    writes <HUB_HOST>:1 / <HUB_HOST>:2 cursors in Redis.
./scripts/seed-last-event.sh

# 2. Build the image (clones the pinned hub-monorepo tag; takes several minutes)
docker compose build

# 3. Start the subscribers
docker compose up -d
docker compose logs -f shuttle-1 shuttle-2
```

Without step 1 the upstream code logs `No last hub event ID found, starting from
the beginning` and consumes whatever event history the node still retains
(~3 days). Check the cursors with:

```bash
./scripts/redis-cli.sh GET "hub:$(grep ^HUB_HOST .env | cut -d= -f2):1:last-hub-event-id"
./scripts/redis-cli.sh GET "hub:$(grep ^HUB_HOST .env | cut -d= -f2):2:last-hub-event-id"
```

## Shards

If the node gains shards, add matching `shuttle-N` services in
`docker-compose.yml` with `SHARDS=<total>` / `SHARD_NUM=<index>`, and bump
`SHARDS` in `.env` so the seed script covers them.

## Optional reconciliation worker

The `shuttle-worker` profile only consumes the reconciliation queue. Start it
when you need backfill/reconciliation:

```bash
docker compose --profile worker up -d
```

Do **not** run `yarn start backfill` (the `backfill` command) for the
"only new events" requirement - it queues historical FIDs for reconciliation.

## systemd

After the first successful `docker compose up -d`, you can let systemd manage it:

```bash
sudo systemctl enable --now shuttle
```

## Pinning / updating

The image is built from the tag in `Dockerfile`:

```dockerfile
ARG HUB_MONOREPO_REF=@farcaster/shuttle@1.0.3
```

Change that tag (or rebuild with `docker compose build --no-cache`) and then
`docker compose up -d` to roll. The upstream package is a library; the image
currently runs its example app. Copy `packages/shuttle/src/example-app` into your
own app when you add a business `MessageHandler` / worker.

## Env

`/opt/shuttle/.env` is generated once with the managed DB/Redis endpoints and
passwords. To rotate a password: update it on the managed instance first, then
edit `.env` and `docker compose up -d`.

## NOTE (added after bootstrap)

- /opt/shuttle/.env is 0600 root:root: run the scripts (and docker unless the
  user is in the docker group) with sudo, e.g. sudo ./scripts/seed-last-event.sh
- All three services share image local/farcaster-shuttle:1.0.3; build it once with
  sudo docker compose build shuttle-1 (building every service may report a benign
  "image already exists" error because they export the same tag).
